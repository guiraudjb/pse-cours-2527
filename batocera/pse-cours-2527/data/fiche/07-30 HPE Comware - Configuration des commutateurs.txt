CONFIGURATION DES COMMUTATEURS HPE SOUS COMWARE 7 (DIFFÉRENCES AVEC COMWARE 5), PARTIE 1 : ENVIRONNEMENT, VLAN, INTERFACES VLAN, SERVEUR ET RELAIS DHCP, ADRESSES FIXES, PORTS ACCESS, TRUNK ET HYBRID, AGRÉGATION STATIQUE ET DYNAMIQUE, MISE EN PILE IRF ET ADMINISTRATION.

LEXIQUE COMPLET.

      Comware est le système d'exploitation réseau des commutateurs et routeurs HPE issus de la gamme H3C, gammes HPE FlexNetwork et FlexFabric.

      Comware 7 est la version actuelle, Comware 5 la version antérieure, encore présente sur d'anciens équipements, avec quelques commandes différentes.

      La vue utilisateur est le mode de départ, signalé par une invite entre chevrons, par exemple <HPE>.

      La vue système est le mode de configuration globale, signalé par une invite entre crochets, par exemple [HPE], obtenue par system-view.

      Une vue d'interface est le mode de configuration d'un port ou d'une interface logique, obtenue par la commande interface.

      La commande display affiche une information, comme show chez d'autres constructeurs.

      La commande undo annule une configuration, comme no chez d'autres constructeurs.

      La commande save enregistre la configuration courante dans le fichier de démarrage.

      Le nommage des ports suit la forme type membre/sous-carte/port, par exemple GigabitEthernet1/0/1.

      Un VLAN est un réseau local virtuel qui segmente le domaine de diffusion, numéroté de 1 à 4094.

      Le port access appartient à un seul VLAN et transmet des trames non étiquetées.

      Le port trunk transporte plusieurs VLAN étiquetés et un seul VLAN non étiqueté, le PVID.

      Le port hybrid, propre à Comware, transmet plusieurs VLAN étiquetés et plusieurs VLAN non étiquetés.

      Le PVID, port VLAN ID, est le VLAN attribué aux trames reçues sans étiquette.

      L'étiquette 802.1Q est le champ de quatre octets inséré dans la trame Ethernet pour indiquer son VLAN.

      L'interface Vlan-interface est l'interface de niveau 3 d'un VLAN, qui porte une adresse IP, équivalente à une SVI.

      Le relais DHCP transmet en unicast au serveur DHCP les demandes diffusées par les postes d'un VLAN.

      L'option 82 est l'information ajoutée par le relais pour identifier le commutateur et le port d'origine de la demande.

      Bridge-Aggregation est l'interface d'agrégation de liens de niveau 2, équivalente à un port-channel.

      L'agrégation statique regroupe des liens sans protocole de négociation, la cohérence étant assurée par la seule configuration.

      L'agrégation dynamique utilise le LACP, link aggregation control protocol, défini par la norme IEEE 802.1AX.

      Un port sélectionné, Selected, transmet le trafic de l'agrégat, un port non sélectionné, Unselected, reste en attente.

      L'IRF, intelligent resilient framework, est la mise en pile qui fait de plusieurs commutateurs un seul équipement logique.

      Le maître IRF, master, gère la pile, les autres membres sont subordonnés, standby.

      La MAD, multi-active detection, détecte la scission d'une pile IRF pour éviter deux maîtres actifs.

      La configuration groupée applique une même configuration à plusieurs ports, par interface range sous Comware 7 et port-group manual sous Comware 5.

      Le rôle utilisateur fixe les droits sous Comware 7, network-admin pour l'administrateur, network-operator pour la lecture seule.

      Les lignes vty sont les accès distants, configurés par line vty sous Comware 7 et user-interface vty sous Comware 5.

COURS DÉTAILLÉ.

I. L'ENVIRONNEMENT COMWARE.

   A. Les vues.

      Après connexion, l'invite <HPE> indique la vue utilisateur.

      La commande system-view ouvre la vue système, l'invite devient [HPE].

      La commande interface GigabitEthernet1/0/1 ouvre la vue du port, l'invite devient [HPE-GigabitEthernet1/0/1].

      La commande quit remonte d'un niveau, return ou Ctrl+Z revient à la vue utilisateur.

      Le point d'interrogation affiche l'aide contextuelle, la touche Tab complète les mots-clés, les commandes peuvent être abrégées.

   B. Les commandes de base.

      La commande sysname SW-ACCES-01 nomme l'équipement.

      Les commandes display current-configuration, display interface brief, display version et display this sont les plus utiles.

      La commande save force enregistre sans confirmation, reset saved-configuration puis reboot rétablissent la configuration usine.

   C. La correspondance avec la syntaxe Cisco.

      show devient display, no devient undo, configure terminal devient system-view, end devient return, write devient save.

      switchport mode access devient port link-type access, interface vlan devient interface Vlan-interface, port-channel devient Bridge-Aggregation.

II. LES VLAN.

   A. La création.

      La commande vlan 10 crée le VLAN 10 et ouvre sa vue.

      Dans cette vue, name SERVEURS donne un nom court et description un libellé libre.

      La commande vlan 20 to 30 crée une plage de VLAN en une fois.

      La commande display vlan brief liste les VLAN et leurs ports.

      Le VLAN 1 existe par défaut et ne peut pas être supprimé, la commande undo vlan 10 supprime un VLAN créé.

   B. Le port access et ses cas d'usage.

      Dans la vue du port : port link-type access, puis port access vlan 10.

      Depuis la vue du VLAN : port GigabitEthernet1/0/1 to GigabitEthernet1/0/10 affecte plusieurs ports access en une fois.

      Cas d'usage : tout équipement terminal qui n'étiquette pas ses trames et n'appartient qu'à un réseau, comme un poste de travail, une imprimante, une caméra, un serveur physique simple ou un contrôleur d'accès.

      Intérêt de sécurité : l'équipement ne choisit pas son VLAN, toute trame étiquetée qu'il enverrait est rejetée, ce qui empêche le saut de VLAN.

      C'est le type de port par défaut et le plus courant sur un commutateur d'accès.

   C. Le port trunk, avec ou sans PVID.

      Dans la vue du port : port link-type trunk, puis port trunk permit vlan 10 20 30, ou port trunk permit vlan all.

      Le trunk transporte plusieurs VLAN étiquetés et au plus un VLAN non étiqueté, le PVID, qui vaut 1 par défaut.

      Trunk sans PVID utilisé : liaison entre deux commutateurs, ou vers un cœur de réseau, où tous les VLAN circulent étiquetés.

      Bonne pratique pour ce cas : retirer le VLAN 1 par undo port trunk permit vlan 1, ou placer le PVID sur un VLAN inutilisé, pour qu'aucune trame non étiquetée ne circule et pour éviter les attaques par double étiquette.

      Trunk avec PVID utile : équipement qui envoie un réseau sans étiquette et les autres étiquetés, comme une borne Wi-Fi dont l'administration est non étiquetée dans le VLAN 99 et les SSID étiquetés dans les VLAN 10 et 20, ou un hyperviseur dont la gestion est non étiquetée.

      Configuration de ce cas : port trunk permit vlan 10 20 99, puis port trunk pvid vlan 99.

      Règle : le PVID doit être identique aux deux extrémités, sinon les trames non étiquetées passent d'un VLAN à l'autre, ce qui crée une fuite entre réseaux et peut perturber le spanning tree.

   D. Le port hybrid et plusieurs VLAN non étiquetés.

      Dans la vue du port : port link-type hybrid, port hybrid vlan 10 untagged, port hybrid vlan 20 tagged, puis port hybrid pvid vlan 10.

      Le PVID décide du VLAN des trames reçues sans étiquette, la liste untagged décide des VLAN dont les trames ressortent sans étiquette.

      Un port hybrid peut donc rendre plusieurs VLAN non étiquetés en sortie, ce qu'un port trunk ne permet pas.

      Cas d'usage 1, téléphone et poste : téléphone IP étiqueté dans le VLAN voix 20 et poste non étiqueté dans le VLAN données 10 sur la même prise, par port hybrid vlan 20 tagged, port hybrid vlan 10 untagged et port hybrid pvid vlan 10.

      Cas d'usage 2, ressource partagée entre VLAN isolés, sans routage : les utilisateurs des VLAN 10 et 20 ne doivent pas se voir, mais tous doivent joindre un serveur ou une imprimante placé dans le VLAN 30.

      Port du serveur : port hybrid pvid vlan 30 et port hybrid vlan 10 20 30 untagged, pour qu'il reçoive sans étiquette les trames des trois VLAN et réponde dans le VLAN 30.

      Ports des utilisateurs du VLAN 10 : port hybrid pvid vlan 10 et port hybrid vlan 10 30 untagged, ceux du VLAN 20 : port hybrid pvid vlan 20 et port hybrid vlan 20 30 untagged.

      Résultat : chaque utilisateur reçoit les réponses du serveur, mais les VLAN 10 et 20 restent isolés l'un de l'autre, sur le principe des VLAN asymétriques.

      Cas d'usage 3, VLAN attribué dynamiquement : avec l'authentification 802.1X ou MAC, le VLAN invité ou le VLAN donné par le serveur RADIUS s'applique non étiqueté sur un port hybrid.

      Limite : plusieurs VLAN non étiquetés sur un même port supposent une conception rigoureuse, documentée, car l'isolation repose sur la cohérence de toutes les listes untagged.

   E. Le changement de type de port.

      Pour passer de trunk à hybrid, il faut d'abord revenir au type access, par port link-type access.

      La commande display port trunk, ou display port hybrid, vérifie la configuration.

   F. La configuration groupée.

      Sous Comware 7, interface range GigabitEthernet1/0/1 to GigabitEthernet1/0/24 configure plusieurs ports d'un coup.

      La commande interface range name POSTES interface GigabitEthernet1/0/1 to GigabitEthernet1/0/24 enregistre un groupe nommé réutilisable.

      Sous Comware 5, port-group manual POSTES puis group-member joue le même rôle.

      Comware ne propose pas de fonction appelée smart port comme les macros Smartports d'autres constructeurs : la configuration groupée en tient lieu.

III. LES INTERFACES VLAN, LE SERVEUR ET LE RELAIS DHCP.

   A. L'interface VLAN.

      La commande interface Vlan-interface 10 crée l'interface de niveau 3 du VLAN 10, qui doit exister.

      La commande ip address 192.168.10.254 24, ou 192.168.10.254 255.255.255.0, attribue l'adresse de passerelle.

      Le mot-clé sub ajoute une adresse secondaire.

      L'interface est active dès qu'au moins un port du VLAN est actif.

      La commande ip route-static 0.0.0.0 0 192.168.0.1 crée la route par défaut, display ip routing-table vérifie la table.

   B. Le serveur DHCP sur l'interface VLAN.

      Cas d'usage : un site sans serveur DHCP, où le commutateur de niveau 3 distribue lui-même les adresses de chaque VLAN.

      La commande dhcp enable active le service, puis dhcp server ip-pool VLAN10 crée la plage d'adresses.

      Dans la vue de la plage : network 192.168.10.0 mask 255.255.255.0, gateway-list 192.168.10.254, dns-list 10.0.0.53, domain-name entreprise.local et expired day 1 pour un bail d'un jour.

      Dans la Vlan-interface 10 : dhcp select server, et dhcp server apply ip-pool VLAN10 pour lier explicitement la plage, sinon la plage est choisie d'après le réseau de l'interface.

      Les adresses fixées à la main, passerelle, imprimantes, serveurs, bornes, sont retirées de la distribution par dhcp server forbidden-ip 192.168.10.1 192.168.10.20, ou forbidden-ip dans la plage.

      Une réservation attribue toujours la même adresse à un équipement : static-bind ip-address 192.168.10.50 mask 255.255.255.0 hardware-address 0011-2233-4455 dans la plage.

      Choix entre adresse statique et réservation : l'adresse statique est configurée sur l'équipement et doit être exclue de la plage, la réservation reste gérée centralement par le DHCP.

      Les commandes display dhcp server ip-in-use, display dhcp server free-ip et display dhcp server statistics suivent les baux.

      Sur une même Vlan-interface, on choisit soit le serveur, soit le relais.

   C. Le relais DHCP.

      La commande dhcp enable active le service DHCP sur l'équipement.

      Dans la Vlan-interface : dhcp select relay, puis dhcp relay server-address 10.0.0.5, plusieurs serveurs pouvant être déclarés.

      La commande dhcp relay information enable ajoute l'option 82.

      Sous Comware 5, les serveurs se déclarent par dhcp relay server-group 1 ip 10.0.0.5 puis dhcp relay server-select 1 dans l'interface.

      La commande display dhcp relay statistics suit les échanges relayés.

IV. L'AGRÉGATION DE LIENS.

   A. L'agrégation statique.

      La commande interface Bridge-Aggregation 1 crée l'agrégat, statique par défaut.

      Dans chaque port membre : port link-aggregation group 1.

      Aucun protocole ne vérifie l'autre extrémité : une erreur de câblage ou de configuration peut provoquer une boucle ou une perte de trafic.

   B. L'agrégation dynamique LACP.

      Dans la vue de l'agrégat : link-aggregation mode dynamic.

      Le LACP échange des messages entre les deux extrémités, appelées acteur et partenaire, et ne sélectionne que les liens cohérents.

      La commande lacp system-priority fixe la priorité du système qui décide, link-aggregation port-priority celle des ports.

      La commande lacp period short accélère la détection de panne.

      La commande link-aggregation selected-port maximum 4 limite le nombre de liens actifs, les autres restant en secours.

   C. Les règles communes.

      Les ports membres doivent avoir la même vitesse, le même duplex et le même type de lien.

      La configuration de VLAN se fait sur l'interface Bridge-Aggregation, qui la propage aux ports membres.

      La commande link-aggregation global load-sharing mode source-ip destination-ip règle la répartition de charge.

      La commande display link-aggregation verbose montre les ports sélectionnés et l'état LACP.

V. LA MISE EN PILE IRF.

   A. Le principe.

      Plusieurs commutateurs reliés par des liens IRF forment un seul équipement logique, avec une adresse et une configuration uniques.

      Le numéro de membre apparaît en premier dans le nom des ports, par exemple GigabitEthernet2/0/1 pour le membre 2.

      Un agrégat peut réunir des ports de membres différents, ce qui supprime le point unique de panne sans spanning tree.

   B. La mise en place.

      Sur le futur membre 2 : irf member 1 renumber 2, puis sauvegarde et redémarrage.

      La commande irf member 1 priority 32 donne la priorité la plus élevée au futur maître.

      Les ports physiques à utiliser pour la pile sont désactivés par shutdown, puis associés : irf-port 1/1, puis port group interface Ten-GigabitEthernet1/0/49.

      La commande irf-port-configuration active applique les ports IRF, puis on réactive les ports physiques et on sauvegarde.

      Le port IRF 1 d'un membre se câble vers le port IRF 2 du membre voisin.

   C. La sécurisation et le suivi.

      La MAD par LACP s'active par mad enable sur un agrégat dynamique relié à un équipement intermédiaire, la MAD par BFD par mad bfd enable sur une Vlan-interface dédiée.

      La commande irf mac-address persistent timer conserve l'adresse MAC de la pile quelques minutes après la perte du maître.

      La commande irf auto-update enable met automatiquement à niveau le logiciel d'un membre qui rejoint la pile.

      Les commandes display irf, display irf topology et display irf configuration vérifient la pile.

VI. L'ADMINISTRATION SÉCURISÉE.

      La commande local-user admin class manage crée un administrateur, avec password hash, service-type ssh et authorization-attribute user-role network-admin.

      Sous Comware 5, les droits s'expriment par authorization-attribute level 3.

      La commande public-key local create rsa génère les clés, ssh server enable active SSH.

      Dans line vty 0 63 : authentication-mode scheme et protocol inbound ssh, puis undo telnet server enable.

POINTS D'ATTENTION.

      Sans save, la configuration est perdue au redémarrage.

      <HPE> pour la vue utilisateur, [HPE] pour la vue système.

      Access pour un terminal, trunk entre équipements de réseau, hybrid pour mêler étiqueté et non étiqueté ou rendre plusieurs VLAN non étiquetés.

      Le PVID doit être identique aux deux extrémités d'un trunk, et un trunk entre commutateurs ne devrait transporter aucune trame non étiquetée.

      Repasser en access avant de changer un port de trunk à hybrid.

      Une agrégation statique ne détecte pas les erreurs de l'autre extrémité : préférer le LACP.

      Configurer les VLAN sur la Bridge-Aggregation et non sur les membres.

      Exclure de la plage DHCP toutes les adresses fixées à la main, ou les gérer par réservation.

      La renumérotation IRF ne prend effet qu'au redémarrage, et une pile sans MAD risque deux maîtres actifs.

      Comware 7 : line vty, user-role, interface range. Comware 5 : user-interface vty, level 3, port-group manual.
